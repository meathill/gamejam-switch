## 1. 概述

| 项目     | 内容                                                                                                     |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 类型     | 2D 横版解谜平台跳跃（puzzle-platformer）                                                                 |
| 引擎     | Godot 4（详见 [TECH_SPEC](./TECH_SPEC.md)）                                                              |
| 参赛     | GitHub Game Off 2026，主题 **SHIFT**，2026-12-01 13:37 PST 截止（[规则](./materials/game-off-2026.md)）  |
| 平台     | Web（itch.io 试玩，评审主要渠道）> Windows / macOS / Linux                                               |
| 一句话   | 被神明托付最后神力的流浪猫，在洪水淹没的城市里切换雨、雪、风、日照四种天气，改变水的状态，救出被困的人。 |
| 本期目标 | 一个可完整游玩的 Demo：序章文游 + 第一关核心谜题段落，5～10 分钟                                         |

### 1.1 与 SHIFT 主题的契合

评分有 Theme Interpretation 一项，现有材料没有出现 “shift”，需要在设计里显式表达：

| 层次     | 表达                                                                         |
| -------- | ---------------------------------------------------------------------------- |
| 核心机制 | **天气切换（shift the weather）**：在四种天气间切换，是全部谜题的入口        |
| 物质状态 | 水在 液态 ↔ 冰面 之间转换，水位在 0/1/2 之间升降，即“相变”与“位移”           |
| 操作     | **Shift 键 = 切换天气**（直接呼应官方 “only buttons are the Shift keys” 梗） |
| 叙事     | 一只流浪猫转变（shift）为神力的承载者；人类最终转变对自然的态度              |
| 视觉     | 猫身后的残缺圆环分四段，切换天气时圆环旋转（shift）到对应段                  |

建议游戏名或副标题带上 Shift/切换，例如《Weather Shift》，**【待确认】**。

## 2. 世界观与角色（摘要）

完整设定见 [story.md](./materials/story.md)。

- **世界**：被洪水淹没的现代城市。人类填埋河道、改成地下暗渠，填湿地、砍山林，暴雨与冰川融水无处可去，爆发山洪。
- **伊尔妲**：掌管自然循环的神，神体破碎，无法亲自出手。背后悬浮的圆环分四段，对应四种天气。
- **小猫（主控）**：流浪猫，得到神力后额头出现金色嫩芽印记、尾尖发光，施法时身后浮现残缺圆环。话很少，句子很短。
  - 美术实际是“穿黄绿色猫耳雨衣的灰猫”，与文案“狸花猫”不一致，**建议以美术为准**，**【待确认】**。
- **NPC**：面目模糊的普通人（Demo 中 2 名居民），其中一位是平时喂猫的老人（“她”）。
- **长线**：城市 → 农田 → 河谷 → 冰山 → 老公园古树。Demo 只做城市第一关。

## 3. 核心玩法

### 3.1 玩家循环

观察当前天气与水位 → 切换天气 → 对选中区域施放 → 观察环境变化 → 选择步行或浮箱路线 → 移动/跳跃 → 救援居民 → 前往高地

### 3.2 操作（建议）

| 动作         | 键盘                           | 手柄            |
| ------------ | ------------------------------ | --------------- |
| 移动         | A/D、←/→                       | 左摇杆 / 十字键 |
| 跳跃         | Space、W、↑                    | A（下）         |
| 切换天气     | **Shift**（下一个）；1～4 直选 | LB / RB         |
| 施放天气     | F                              | X（左）         |
| 互动（救援） | E                              | Y（上）         |
| 重开 / 暂停  | R / Esc                        | Select / Start  |

### 3.3 目标区域选择

材料要求“对当前选中的环境区域执行一次天气变化”，但未说明怎么选。**建议**：

- 每个水域有一个“影响范围”，小猫进入范围即自动选中该水域；范围重叠时选距离最近的。
- 选中的水域显示描边高亮，HUD 显示：区域名、水位、状态（液态/冰面/污染）。
- 不做鼠标点选（手柄与 Web 一致性更好）。**【待确认】**

### 3.4 天气规则

一次施放只作用于选中水域，只产生**一步**变化。无效施放不改变状态，但必须显示原因。

| 天气 | 生效条件                                          | 效果                                   | 无效时提示                                   |
| ---- | ------------------------------------------------- | -------------------------------------- | -------------------------------------------- |
| 雨   | 液态，且水位 < 2                                  | 水位 +1；水中浮箱随水面上浮            | “水位已满” / “冰面无法涨水”                  |
| 雪   | 液态，且水位 ≥ 1                                  | 结冰，保留水位；冰面可行走             | “这里没有水” / “已经结冰”                    |
| 风   | 液态，水位 = 2，区域内有浮箱                      | 浮箱沿停靠点向**小猫面朝方向**移动一格 | “浮箱被冻住了” / “水太浅” / “前方没有停靠点” |
| 日照 | 冰面 → 融化为同水位液态；液态且水位 ≥ 1 → 水位 −1 | 见左                                   | “已经干了” / “污染水无法蒸发”                |

- 日照对冰面只融化、不降水位，再施放一次才降水位（保证“一步一变化”，因果清晰）。
- 风向原文只说“沿预设停靠点移动一格”，未说明方向。**建议**：风向 = 小猫面朝方向，玩家通过站位决定推哪边。**【待确认】**

### 3.5 水位与状态

| 水位   | 液态：小猫                 | 液态：浮箱         | 冰面：小猫               |
| ------ | -------------------------- | ------------------ | ------------------------ |
| 0 干燥 | 正常行走                   | 搁浅，不可移动     | —（无水不能结冰）        |
| 1 浅水 | 可通过，移动减速           | 搁浅停靠，不可移动 | 可行走，滑行             |
| 2 深水 | 不能通过，落水则回到检查点 | 漂浮，可被风推动   | 可行走，滑行；浮箱被冻住 |

- **污染水（枯痕）**：灰紫色，日照无效。Demo 中用于强制玩家走“启动排水站”的路线（见 4.2）。

### 3.6 救援

- 居民原地等待，不自由移动。小猫到达居民旁按 E 触发救援，居民播放转移动画后进入安全点（Demo 中直接淡出 + 计数）。
- 救出全部 2 名居民并抵达高地避难所 = 通关。
- 种下自然种子：可选目标，不影响通关。

## 4. 第一关

原始设计见 [schedule.md](./materials/schedule.md)。完整关卡设计尚未定稿，Demo 先做一个**压缩版**，确保四种天气都要用到、且不是按固定顺序用。

### 4.1 区域（原始）

A 起点城市低地 → B 积水街道 → C 废弃排水站 → D 被淹广场 → E 居民楼 → F 浮箱转运区 → G 高地避难所 → H 城市边缘（支路：城市绿化修复点）

### 4.2 Demo 关卡流程（建议）

| 段  | 区域                 | 谜题                                                                                                              | 用到的天气          |
| --- | -------------------- | ----------------------------------------------------------------------------------------------------------------- | ------------------- |
| 1   | A 城市低地           | 教学：移动、跳跃，看到洪水和远处居民楼的手电光                                                                    | —                   |
| 2   | B 积水街道           | 深水阻断道路 → 雪天结冰走过去（或日照降到浅水趟过去）                                                             | 雪 / 日照           |
| 3   | C 排水站             | 排水槽水位 0 → 雨天涨到 2，排水站启动                                                                             | 雨                  |
| 4   | D 被淹广场           | 广场是污染深水，日照无效；排水站启动后降为浅水清水 → 趟水到公交站救居民 2                                         | （联动）/ 日照      |
| 5   | E+F 居民楼与浮箱水道 | 雨天把水道涨到 2 → 风天把浮箱推到居民楼下 → 浮箱随水位上浮到二层窗口 → 救居民 1；中途需要日照融冰解锁被冻住的浮箱 | 雨 / 风 / 日照 / 雪 |
| 6   | G 高地避难所         | 结算：居民抵达，雨声减弱，显示通关                                                                                | —                   |

- H 城市边缘、绿化支路：Demo 不做，放入 TODO。
- 关卡验收重点（原文）：玩家不是按顺序使用四个技能，而是根据环境在四种天气间切换；雨涨水、雪结冰、风移箱、日照融冰退水要形成**可观察、可推理、可验证**的因果链。

### 4.3 原始材料中的冲突与缺口

| #   | 问题                                                                     | 建议                                                      |
| --- | ------------------------------------------------------------------------ | --------------------------------------------------------- |
| 1   | B 区：节点表写“日照降低水位”，路线表写“雪天结冰”                         | 两种解法都允许                                            |
| 2   | 居民 2“需要先启动排水站”，但排水站如何影响广场没有定义                   | 广场设为污染水，日照无效；排水站启动后广场水位 −1 并净化  |
| 3   | 地图顺序 E 在 F 前，但 E 的救援依赖 F 的浮箱，形成回头路                 | 把 E、F 合并成同一段水道，居民楼就立在浮箱水道旁          |
| 4   | 居民 1 在“二层窗口”，浮箱如何到达高处未定义                              | 利用“雨让浮箱浮到高处”的设定：水位 2 时浮箱顶部与窗口齐平 |

| 9   | 浮箱 / 木箱 叫法不一                                                     | 统一为“浮箱”，美术表现为木箱                              |
| 10  | 文案里雨“让垃圾桶、木板浮起”，日照“让植物长出可攀爬的藤”，第一关未使用   | Demo 不做，留给后续关卡                                   |

## 5. 序章（文游）

- 对白全文见 [dialogue.md](./materials/dialogue.md)。
- 表现：全屏背景 + 立绘/剪影 + 对话框（角色名、文本逐字显示）+ 点击/按键推进 + 跳过。
- 演出节点：雨夜洪水 → 屋顶小猫 → 对面楼手电光 → 白光与残缺圆环 → 对话 → 选择“接受” → 嫩芽印记、圆环亮起一段 → 种子落下 → 标题 → 第一关开场对白。
- 原文要求“序章要展示四种天气的基本效果”：在伊尔妲介绍四种天气的四句台词处，各配一次全屏天气演出。
- 第一关开场保留序章最后的画面（转场无缝衔接）。

## 7. Demo 范围与验收

### 7.1 必须有（MVP）

1. 小猫移动、跳跃、碰撞，接入现有行走/跳跃/施法帧
2. 四种天气切换与施放，规则严格按 3.4，无效施放有提示
3. 水位 0/1/2 与液态/冰面的视觉、碰撞、移动速度同步变化
4. 浮箱：风推动、随水位升降、结冰锁定、可承载小猫
5. 两名居民救援、检查点、落水重生、通关、重开
6. HUD：当前天气、选中区域水位与状态、救援进度
7. 序章文游（可先用占位图）
8. Web 导出可在 itch.io 正常游玩

### 7.2 可以有

- 种子与绿化支路、H 城市边缘结尾演出
- 冰面滑行手感打磨、粒子天气特效、音效完善
- 桌面平台导出包

### 7.3 验收标准

- 新玩家不看说明，能在 10 分钟内通关
- 每次施放后 0.5 秒内，水位、地形、浮箱状态、可通行路线全部更新完毕
- 不存在卡死（任何状态下都能通过重开或天气组合恢复）
- 至少 3 人完成试玩并记录问题
